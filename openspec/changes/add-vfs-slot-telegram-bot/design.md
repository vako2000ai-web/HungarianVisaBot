# Design

## Context

Репозиторий пуст. Портал VFS (`services.vfsglobal.by/blr/ru/hun`) — SPA на Angular за Cloudflare с Turnstile на входе; публичного API слотов нет. Статус слотов виден на шаге «Информация о подаче документов» после выбора центра, категории и подкатегории. Мотивация — см. proposal.md.

## Goals / Non-Goals

**Goals:**
- Надёжно и редко (не чаще раза в минуту) определять наличие слотов и мгновенно уведомлять.
- Минимум ручной работы: вход вручную раз в срок жизни сессии.

**Non-Goals:**
- Автоматическое бронирование, заполнение данных заявителя, оплата.
- Обход капчи/Cloudflare, мультиаккаунтность, ротация прокси.
- Веб-интерфейс.

## Decisions

- **Стек: Node.js 22 + TypeScript.** Один язык с Playwright и grammY; близок стеку владельца. Альтернатива — Python (aiogram + playwright): равноценно, отклонено ради единого стека.
- **Браузер: Playwright (Chromium) с persistent context** (`userDataDir`). SPA и Cloudflare не позволяют стабильно ходить обычным HTTP-клиентом; постоянный профиль сохраняет cookies. Альтернатива — перехват внутреннего API по cookies: хрупко и ближе к обходу защиты, оставлено как возможная оптимизация.
- **Вход вручную:** режим `login` запускает видимый браузер, владелец проходит Cloudflare и вводит данные; проверки идут в headless/headed по настройке. Автоввод пароля не используется, чтобы не хранить секрет.
- **Telegram: grammY, long polling.** Не требует публичного адреса; подходит для домашнего сервера/VPS.
- **Определение статуса:** по тексту сообщения «нет доступных слотов» (с набором синонимов на ru/en) и состоянию кнопки «Продолжить»; всё остальное — `UNKNOWN`. Селекторы и тексты вынесены в один модуль для лёгкой правки.
- **Состояние:** JSON-файл (`state.json`) с последним статусом, временем и счётчиками; SQLite избыточен для одного ключа.
- **Планировщик:** цикл с интервалом `CHECK_INTERVAL_SEC` (по умолчанию 180, минимум 60) ± 20% jitter; экспоненциальная задержка при блокировках.
- **Конфигурация:** `.env` (`TELEGRAM_BOT_TOKEN`, `ALLOWED_USER_IDS`, `VFS_CENTER`, `VFS_CATEGORY`, `VFS_SUBCATEGORY`, `CHECK_INTERVAL_SEC`, `PROFILE_DIR`); валидация при старте.
- **Развёртывание:** процесс на машине владельца или VPS с Xvfb/headed-режимом для периодического входа; Dockerfile опционально.

## Risks / Trade-offs

- [Изменение вёрстки/текстов портала] → изолированный модуль селекторов, статус `UNKNOWN` вместо ложного «есть слоты», оповещение о серии сбоев.
- [Блокировка IP/аккаунта за частые запросы] → интервал ≥ 60 с с jitter, backoff, один аккаунт и один браузер.
- [Cloudflare требует ручного прохождения] → запрос вмешательства владельца, без обхода.
- [Нарушение условий использования VFS] → только наблюдение с лёгкой нагрузкой; решение об использовании остаётся за владельцем.
- [Утечка токена/учётки] → `.env` и профиль в `.gitignore`, секреты не логируются.
- [Слот занимают за секунды] → мгновенное уведомление со ссылкой; бронирует человек.
