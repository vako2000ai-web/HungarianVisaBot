# Spec Delta

## Purpose

Периодически определять, есть ли свободные слоты записи на подачу документов для настроенной категории визы, и выявлять момент, когда статус меняется.

## ADDED Requirements

### Requirement: Проверка настроенной категории
Система SHALL проверять доступность слотов для центра, категории и подкатегории, заданных в конфигурации (по умолчанию: Hungary Visa Application Center, Minsk / short term visa C / Short-Term VISA 90 days).

#### Scenario: Используются значения по умолчанию
- **WHEN** конфигурация не переопределяет центр, категорию и подкатегорию
- **THEN** проверяется комбинация Minsk / short term visa C / Short-Term VISA 90 days

#### Scenario: Категория не найдена на портале
- **WHEN** настроенный центр, категория или подкатегория отсутствуют в выпадающих списках
- **THEN** проверка завершается статусом ошибки и владелец получает оповещение о несовпадении конфигурации

### Requirement: Определение статуса слотов
Система SHALL классифицировать результат проверки как `NO_SLOTS`, `SLOTS_AVAILABLE` или `UNKNOWN`.

#### Scenario: Слотов нет
- **WHEN** страница показывает сообщение «нет доступных слотов для записи»
- **THEN** статус равен `NO_SLOTS`

#### Scenario: Слоты есть
- **WHEN** сообщение об отсутствии слотов не показано и кнопка «Продолжить» доступна
- **THEN** статус равен `SLOTS_AVAILABLE`

#### Scenario: Результат неоднозначен
- **WHEN** страница не загрузилась, сессия потеряна или разметка не соответствует ожидаемой
- **THEN** статус равен `UNKNOWN`, а предыдущий известный статус не изменяется

### Requirement: Периодичность и нагрузка
Система SHALL запускать проверки с настраиваемым интервалом со случайным разбросом и интервалом не менее 60 секунд.

#### Scenario: Интервал ниже минимума
- **WHEN** в конфигурации задан интервал меньше 60 секунд
- **THEN** система отклоняет конфигурацию при старте с понятной ошибкой

#### Scenario: Ограничение запросов со стороны портала
- **WHEN** портал отвечает ограничением частоты или блокировкой
- **THEN** система увеличивает интервал (экспоненциальная задержка) и сообщает владельцу

### Requirement: Обнаружение изменений
Система SHALL фиксировать переход между статусами и публиковать событие только при смене определённого статуса (`NO_SLOTS` ⇄ `SLOTS_AVAILABLE`).

#### Scenario: Появились слоты
- **WHEN** предыдущий статус `NO_SLOTS`, а новая проверка вернула `SLOTS_AVAILABLE`
- **THEN** публикуется событие «слоты появились» с временем проверки

#### Scenario: Статус не изменился
- **WHEN** две проверки подряд вернули `NO_SLOTS`
- **THEN** событие не публикуется

#### Scenario: Состояние переживает перезапуск
- **WHEN** процесс перезапущен
- **THEN** последний известный статус восстанавливается, и повторное уведомление о том же статусе не отправляется
